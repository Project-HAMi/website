HAMi 实战课程是一条有明确起点和终点的学习路径。所有章节围绕同一个故事：一个小型 AI 团队、一套 GPU 集群，以及他们在成长过程中依次遇到的问题。每一章先复现一个问题，再讲背后的原理，然后展示 HAMi 如何解决它。

## 适合谁

你了解基本的 Linux 和 Kubernetes（Pod、Deployment、`kubectl`），但从未在 Kubernetes 上使用过 GPU，或者用过但不清楚其中的原理。不需要任何 HAMi 基础。

完成本课程后，你应该能够：

- 说清 GPU 在 Kubernetes 中从硬件到调度的完整路径，以及原生方案的不足
- 说清 HAMi 每个组件解决什么问题、在哪一步介入
- 在真实 GPU 环境中部署 HAMi，并验证共享、隔离和调度策略
- 在 HAMi 切分出的 GPU 上运行真实的推理负载
- 出现问题时逐层定位原因

## 故事背景

一个小型 AI 团队从一台 GPU 服务器起步。随着团队、模型和服务不断增长，他们接连遇到各种问题：GPU 不够用、邻居干扰、资源碎片、多个团队争抢资源，以及线上故障。每一章是故事的一个阶段，并且都在上一章留下的集群上继续。

## 学习路径

| 章节 | 场景 | 你将学到 |
| --- | --- | --- |
| [1. 准备环境](./setup.md) | 团队检查第一个 GPU 节点 | GPU 软件栈的 5 层结构，以及为什么在 HAMi 登场之前要自底向上逐层检查 |
| [2. 一张卡，一个 Pod](./one-gpu-one-pod.md) | 团队部署第一个模型 | Device Plugin 机制，以及为什么原生 GPU 资源只能整卡分配 |
| 3. 那就共享吧 | 多个 Pod 共享一张 GPU | time-slicing、MPS 和 MIG 能做什么、不能做什么，以及调度和隔离的区别 |
| 4. HAMi 登场 | 团队需要切分和隔离 | Pod 经过 Webhook、调度器扩展、Device Plugin 和 HAMi-core 的完整路径 |
| 5. 卡多了，放哪儿 | 集群扩展到多卡、多节点 | 调度策略、打分机制，以及碎片是如何产生的 |
| 6. 跑真实模型 | 在共享卡上运行推理服务 | 推理引擎如何在切分后的卡上管理显存 |
| 7. 看得见 | 谁用了多少 | 分配视角与使用视角的区别，以及指标从何而来 |
| 8. 多团队与配额 | 多个团队争抢 GPU | 准入控制与调度如何分工 |
| 9. 出故障了 | 线上故障 | 沿 5 层模型自底向上诊断 |
| 10. 下一步 | 深入学习 | 进入现有的[实验](/zh/tutorials/category/labs) |

没有链接的章节仍在编写中。

## 实验环境

主线全程使用真实的 NVIDIA GPU。从一台挂载单张 NVIDIA T4 的云虚拟机开始，在第 5 章扩展到多卡、多节点。每一章都会注明验证时使用的版本。

## 每章的结构

每一章都遵循相同的结构：

1. **场景**：团队在本章遇到了什么
2. **你将理解**：本章讲解的概念
3. **先看问题**：用真实输出复现痛点
4. **背后的原理**：讲清机制，并链接到对应的概念文档
5. **动手解决**：步骤、真实输出，以及每一步的原因
6. **验证**：证明结论成立的证据
7. **常见问题**：最容易犯的错误以及排查方法
8. **自测**：几个检验理解程度的问题
9. **交接**：下一章所需的环境状态
10. **延伸阅读**：相关概念文档和实验

每一章的命令和输出都来自所注明环境中的真实运行。

## 实战课程还是实验？

想从零开始系统学习 HAMi，请走实战课程。想验证某个具体功能或集成，请看[实验](/zh/tutorials/category/labs)。实战课程会在合适的位置链接相关实验，作为选修内容。
